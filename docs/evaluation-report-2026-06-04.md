## 3. 잘된 점

### ① 단일 데이터 소스 (`data.js`) 설계
모든 이력 데이터를 `js/data.js` 한 파일에 집중시켜, 추후 내용 수정 시 HTML·CSS를 건드리지 않고 데이터만 수정하면 전체 반영되는 구조를 설계하였다. 유지보수성이 높다.

### ② 5-팔레트 테마 시스템
CSS 변수(`--clr-accent`, `--clr-accent-rgb`, `--clr-accent-glow` 등)를 계층적으로 설계하여, 팔레트 추가 시 테마 CSS 파일 하나만 작성하면 전체 사이트에 즉시 적용되는 확장 가능한 구조를 만들었다. `localStorage`로 선택 상태를 유지하여 사용자 경험도 챙겼다.

### ③ 하드코딩 컬러 제거
초기 구현에서 산발적으로 사용된 `rgba(201,108,191,...)` 같은 하드코딩 색상을 전부 CSS 변수로 교체함으로써, 테마 전환 시 파티클·그림자·버튼·배지 등 모든 요소가 일관성 있게 변경된다.

### ④ GitHub Actions 기반 완전 자동 배포
`main` 브랜치 push 시 자동으로 빌드·배포되는 파이프라인을 구성하여, 코드 수정 후 별도 작업 없이 2~3분 내 라이브 반영이 이루어진다.

### ⑤ OG 이미지 브라우저 렌더링 방식
node-canvas 방식의 한글 깨짐 문제를 Playwright headless Chromium으로 전환하여 해결하였다. 결과적으로 실제 Google Fonts가 로드된 상태로 렌더링되어 최고 품질의 이미지가 생성되었다.

## 4. 개선이 필요한 점

### ① 파티클 선 연결 알고리즘 (O(n²))
현재 80개 파티클의 거리 계산이 매 프레임 O(n²) = 6,400회 반복된다. 파티클 수가 증가하면 성능 저하가 발생할 수 있다.
- **개선 방향**: 공간 분할(Grid Cell) 또는 쿼드트리 구조 도입

### ② 연락처 폼 백엔드 연동
현재 `mailto:` 방식으로 이메일 앱을 여는 방식이라, 이메일 앱이 설치되지 않은 환경에서는 동작하지 않는다.
- **개선 방향**: Formspree, EmailJS 등 서버리스 폼 서비스 연동

### ③ 프로젝트 섹션 데이터 미입력
`data.js`의 `projects: []` 가 비어 있어 프로젝트 섹션이 안내 문구만 표시된다.
- **개선 방향**: 실제 프로젝트 데이터(스크린샷, GitHub 링크, 설명) 입력

### ④ 이미지 최적화 (WebP 미적용)
프로필 사진이 `.jpg` 원본 그대로 사용된다.
- **개선 방향**: WebP 포맷 변환으로 로딩 속도 추가 개선

### ⑤ 다국어 미지원
현재 한국어 단일 언어로만 구성되어 있다.
- **개선 방향**: `lang` 토글 버튼으로 한/영 전환 기능 추가 고려
